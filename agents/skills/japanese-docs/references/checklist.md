# レビューチェックリスト

## 1. 機械的に検出できる項目（先にスクリプトで潰す）

人が読む前に、このスキルの`scripts/check.py`で検査して直す。コードブロックとインラインコードの中身は検査しない（和欧間スペースだけはインラインコードの前後も見る）。

```sh
python <このスキルのディレクトリ>/scripts/check.py <対象ファイル>...
```

出力は`<ファイル>:<行>:<列>: <分類>（<参照先>）: <ヒットした文字列>`の形式で、ヒットがあれば終了コード1を返す。

ヒットした箇所は基本的に参照先の置き換えを適用する。ただし「事」「為」を含むパターンは、「事件」「事故」「事業」「仕事」「大事」「工事」「行為」「為替」のような実質名詞の一部にもヒットする。形式名詞（〜する事、〜た事、〜という事が、〜の為）かどうかを確認してから置き換える。

## 2. 表記

- [ ] `references/orthography.md`の各節（チームの決定事項、漢字とひらがな、送り仮名、数字、記号、日付・時刻、用語統一表）に沿っている

## 3. 文

- [ ] 一文で言っていることが一つである（「〜し、〜し、〜する」の長い連鎖を分割できないか確認する）
- [ ] 主語と述語の対応が取れている
- [ ] `references/ng-phrases.md`の表現が残っていない
- [ ] `SKILL.md`の「構成と論証の規則」のうち、事実と推測の分離、因果の機構を満たしている

## 4. 段落

- [ ] `SKILL.md`の「構成と論証の規則」のうち、段落と箇条書きの規則を満たしている
- [ ] 前の段落との関係が、接続表現か文脈で明示されている

## 5. 文書全体

- [ ] `SKILL.md`の「構成と論証の規則」のうち、冒頭の要点、見出し、前方参照の規則を満たしている
- [ ] 各見出しが、その節の対象・問い・情報の種類を示している
- [ ] `SKILL.md`の「変更してはいけないもの」を変更していない

## 文書種別ごとの追加チェック

### 障害報告

- [ ] 時系列が発生順に並んでいる
- [ ] 事実（ログ・計測値）と推測が、文として分離されている
- [ ] 恒久対応の担当者と期限が明記されている

### ADR・設計書

- [ ] 決定した内容が冒頭でわかる
- [ ] 決定の理由が書かれている
- [ ] 検討して却下した案が、却下理由とともに書かれている

### PR・Issueの説明

- [ ] 変更点が箇条書きまたは1段落で明確である
- [ ] 動作確認の方法が書かれている
- [ ] 影響範囲（互換性、既存機能への影響）が書かれている

### 手順書

- [ ] 操作指示が文書の文体に合い、操作を直接示している（「保存する」「保存してください」など）
- [ ] 前提条件（環境、権限、事前に必要な作業）が手順の前に書かれている
- [ ] 条件分岐で条件と操作が対応し、文書の文体に合っている

### UI文言・エラーメッセージ

- [ ] 文字数が画面の制約内である
- [ ] ユーザーの操作ミスを責める表現になっていない（「不正な入力です」→「入力内容を確認してください」）
- [ ] 次に何をすればよいかが示されている
