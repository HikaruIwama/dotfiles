# 文の組み立て

`SKILL.md`の「文の組み立て」の各原則について、なぜそうなるか、判定の問い、例、原則に反したときによく現れる形を示す。よく現れる形の表は判断の例であり、網羅していない。表にない言い回しも判定の問いで判断し、表の形でも原則に反していなければ直さない。

## 一文に一つの事柄を書く

日本語は文末まで述語が来ないので、読み手は文末に着くまで、その文が何を言うのかを保留して読む。「〜し、〜し、〜する」と事柄をつなぐと、保留が長くなり、どの述語がどの事柄に対応するのかを見失う。

- 判定：この文の言いたいことを、一つの述語で言えるか。
- 悪い例：「設定を変更し、サービスを再起動し、ログを確認したところ、エラーは解消していたが、応答時間が増えていた。」
- 良い例：「設定を変更してサービスを再起動した。エラーは解消したが、応答時間が増えた。」

目安として、100字を超える文、読点が4つ以上ある文は分けられないか確認する。

## 述語に中身を入れる

日本語の文は文末の述語で決まる。動作を名詞にして「行う」「可能である」「必要がある」のような中身のない動詞で受けると（機能動詞結合）、述語が空になる。

- 判定：述語を読んで、何をするのか、どういう状態なのかがわかるか。
- 悪い例：「設定ファイルの確認を行うことが必要である。」
- 良い例：「設定ファイルを確認する。」

| よく現れる形 | 直し方 | 理由 |
| --- | --- | --- |
| 〜することができる／〜することが可能である | 〜できる | 「こと」で名詞にしてから、もう一度述語を足している |
| 実装を行う／確認を行う | 実装する／確認する | 動作が名詞に入り、述語の「行う」に中身がない |
| 〜する必要がある（単なる行動の指示として） | 〜する | 主語が明確な指示なら、義務の言い回しを足さずに言い切る |

## 確信度は文末で一度だけ示す

文は、事柄（命題）と、それに対する書き手の態度（モダリティ）でできている。態度は「〜する」「〜だろう」「〜かもしれない」のように文末で示す。根拠の強さに合わせて一つ選び、重ねない。

- 判定：文末の確信度が、書いた根拠に見合っているか。
- 悪い例：「原因はキャッシュの不整合である可能性があると考えられる。」
- 良い例（ログで確認済み）：「原因はキャッシュの不整合である。」
- 良い例（未確認）：「原因はキャッシュの不整合と推測する。ログでは確認できていない。」

| よく現れる形 | 直し方 | 理由 |
| --- | --- | --- |
| 〜である可能性があると考えられる | 根拠に合わせて「〜である」「〜と推測する」のどちらかにする | 推量を重ねて、書き手の確信度がわからない |
| 1段落にヘッジ（「〜ことがある」「〜場合がある」「〜可能性がある」）が2つ以上 | 根拠のあるものは断定し、残りを一つにまとめる | 段落全体の確信度がわからない |
| あまり推奨されません／注意が必要です（判断を求められる場面での結論として） | 「非推奨」「〜しない」のように言い切る。手順書、ADR、レビュー指摘で特に | 根拠があるのに態度をぼかしている |
| 〜に他ならない | 主張の内容をそのまま書く | 根拠を足さずに確信度だけを上げている |
| ケースバイケース／一概には言えません（文書の結論として） | 判断を下す。下せない場合は、下せない理由を具体的に書く | 態度を示さずに文を終えている |

「〜と言えるだろう」「かもしれない」のような推量は、根拠なく主張を弱めている場合だけ削り、根拠があれば断定する。未確認の事実、確度の低い推測を表す場合は残す（`SKILL.md`の「事実と推測を分離する」を優先する）。

## 動作主を読み手がたどれるようにする

日本語では、文脈からわかる主語を省ける。省いてよいのは、誰の動作かを読み手が補える場合だけである。行為者を書かずに済ませるための受動態（「〜が求められる」「〜とされている」）は、誰が何をするのかを読み手から隠す。

- 判定：この文の動作を誰がするのか、読み手が答えられるか。
- 悪い例：「リリース前に負荷試験の実施が求められる。」
- 良い例：「リリース前に、インフラチームが負荷試験を実施する。」

| よく現れる形 | 直し方 | 理由 |
| --- | --- | --- |
| 対応が必要とされている | 〇〇チームが〇月〇日までに対応する | 誰が対応するか不明 |
| 修正が求められる | レビューで指摘された内容を〇〇が修正する | 誰が求め、誰が直すか不明 |
| 対応する／実施する／検討する（単独で結論として使う） | 担当者、作業内容、期限を明記する | 誰が何をするか不明 |
| 業界の専門家によると／調査結果が示すように（出典不明のまま） | 「〇〇社が公表した△△調査では」のように具体的に書く。出せないなら自分の見解と明記する | 誰が言ったかが不明で、読み手が検証できない |

無主語の受動態は、行為者を主語にした能動態に直す。行為者が本当に不明な場合は、不明であることを明記する（「原因は現時点で不明」）。

## 英語の構文を写さない

英語の構文をそのまま訳すと翻訳調になる。英語に直訳し戻すと自然な英文になるのに、日本語としては硬い文は、組み立てから見直す。

- 判定：この文は、日本語で最初から書いても同じ組み立てになるか。
- 悪い例：「このデータは、移行が予定どおり進んでいることを示している。」
- 良い例：「このデータから、移行が予定どおり進んでいることがわかる。」

| よく現れる形 | 直し方 | 元の英語の型 |
| --- | --- | --- |
| 重要なのは〜である | 主張をそのまま書く | It is important to note that… |
| 本ドキュメントでは〜について見ていく | 結論を先に書く | In this document, we will explore… |
| 掘り下げる／深掘りする | 何をどう調べた・書いたかを書く | delve into |
| データの直後に「〜を示しており」「〜を物語っている」と続けて意義付けする | 「〜から〜がわかる」と書く。評価を書くなら、根拠になる数値・条件を示す | The data shows… / speaks to… |
| 「Xではない。Yだ。」「単なるXではなく、Yだ。」 | Yだけを直接書く | It's not just X, it's Y. |

## 長い修飾語を先に置く

日本語では修飾語が被修飾語の前に積み重なる。修飾語が複数あるときは、長いものを先に、短いものを後に置く。長い修飾語の後に読点を打つと、どこまでが一つの修飾語かがわかる。

- 判定：各修飾語がどの語に掛かるか、一度読んで決まるか。
- 悪い例：「詳しく障害が発生した原因を調べる。」（「詳しく」が「発生した」に掛かるようにも読める）
- 良い例：「障害が発生した原因を詳しく調べる。」

## 文と文の関係を一つ選んで示す

接続詞は、前の文との論理関係（因果、逆接、並列、補足）を表す。関係を決めないまま「また」「さらに」でつなぐと、論理を書かずに済ませることになる。関係が文脈から明らかなら、接続詞は省いてよい。

- 判定：前の文との関係を一語で言えるか。言えるなら、その関係を表す接続詞にするか、省く。
- 悪い例：「キャッシュを無効にした。また、応答時間が2倍になった。」
- 良い例：「キャッシュを無効にした結果、応答時間が2倍になった。」

| よく現れる形 | 直し方 | 理由 |
| --- | --- | --- |
| 1段落に「さらに」「また」「加えて」で始まる文が2つ以上 | 前の文との関係（因果、逆接、並列、補足）を決め、それを表す接続にする。関係が文脈から明らかなら削る | 関係を決めずに文を足している |

## 具体的な動作は具体的な語で書く

「適切に」「柔軟に」「多角的に」のような抽象語や、カタカナのビジネス用語は、指す範囲の解釈を読み手に任せてしまう。何をどこまでするかを、動作、対象、条件で書く。

- 判定：この語を読んで、読み手が同じ作業を再現できるか。
- 悪い例：「エラー時は適切にハンドリングする。」
- 良い例：「タイムアウトしたら3回まで再試行し、それでも失敗したら呼び出し元に例外を返す。」

| よく現れる形 | 直し方 | 理由 |
| --- | --- | --- |
| 適切に処理する | 3回まで再試行し、失敗したらSlackに通知する | 何をするか不明 |
| 柔軟に対応する | 設定ファイルで再試行回数を変更できるようにする | 何をするか不明 |
| 基本的に問題ない | 〇〇の場合を除き問題ない | 例外の条件が不明 |
| 必要に応じて実施する | エラー率が5%を超えた場合に実施する | 実施の条件が不明 |
| 多角的に分析すると | 何をどう見たかを書く | 何を見たのか不明 |
| 包括的に／総合的に | 対象範囲を具体的に書く | 範囲が不明 |
| 非常に／極めて／大いに | 数値や具体的な程度で示す | 程度が不明 |
| 〜という形で／〜という観点から／〜という側面から | 新しい情報がなければ削る | 指す内容がない |

カタカナのビジネス用語は、和語・漢語に言い換えられないか確認する。API、デプロイ、リポジトリのように技術用語として定着している語はそのままでよい。カタカナ語が3語以上連続したら、言い換えを疑う。

| よく現れる形 | 直し方 |
| --- | --- |
| 〜にレバレッジを効かせる | 〜を活用する |
| ソリューション | 解決策、仕組み |
| イノベーティブな | 新しい、独自の |
| 〜にコミットする | 〜を引き受ける、必ず〜する |
| 〜をアラインする | 〜を揃える、〜を合わせる |
| 〜にディープダイブする | 〜を詳しく調べる |
| 〜をスケールする | 〜を拡大する |
| 〜にピボットする | 〜に方針転換する |
