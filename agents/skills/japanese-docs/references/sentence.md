# 文の組み立て

`SKILL.md`の「文の組み立て」に並べた組み立て方ごとに、なぜそうなるのか、見るところ、例、反したときによく出る形をまとめた。よく出る形の表は例であって、全部を挙げたものではない。表にない言い回しも見るところで判断し、表にある形でも組み立て方に反していなければ直さない。

## 一文に一つのことを書く

日本語は述語が文末に来るので、読み手は文末に着くまで、その文が何を言いたいのかを保留しながら読む。「〜し、〜し、〜する」と次々につなぐと保留が長くなり、どの述語がどの話に対応するのかを見失う。

- 見るところ：その文の言いたいことを、一つの述語で言えるか。
- 悪い例：「設定を変更し、サービスを再起動し、ログを確認したところ、エラーは解消していたが、応答時間が増えていた。」
- 良い例：「設定を変更してサービスを再起動した。エラーは解消したが、応答時間が増えた。」

100字を超える文や、読点で節を何度もつないだ文は、分けられないか見てみる。

## 述語に中身を入れる

日本語の文は、文末の述語で意味が決まる。動作を名詞にして「行う」「可能だ」「必要がある」で受けると（機能動詞結合）、述語が空っぽになる。

- 見るところ：述語だけ読んで、何をするのか、どんな状態なのかがわかるか。
- 悪い例：「設定ファイルの確認を行うことが必要である。」
- 良い例：「設定ファイルを確認する。」

| よく出る形 | 直し方 | 理由 |
| --- | --- | --- |
| 〜することができる／〜することが可能だ | 〜できる | 「こと」で名詞にしてから、述語をもう一度足している |
| 実装を行う／確認を行う | 実装する／確認する | 動作が名詞のほうに入って、「行う」には中身がない |
| 〜する必要がある（ただ行動を指示したいとき） | 〜する | 誰がするか明らかな指示なら、義務の言い回しを足さずに言い切る |

## 確かさは文末で一度だけ示す

文は、書いている事柄（命題）と、それをどれだけ確かだと思っているかという書き手の態度（モダリティ）でできている。態度は「〜する」「〜だろう」「〜かもしれない」のように文末に出る。根拠の強さに合わせて一つ選び、重ねない。

- 見るところ：文末の確かさが、書いた根拠に見合っているか。
- 悪い例：「原因はキャッシュの不整合である可能性があると考えられる。」
- 良い例（ログで確かめた）：「原因はキャッシュの不整合だ。」
- 良い例（まだ確かめていない）：「原因はキャッシュの不整合だと推測している。ログではまだ確かめていない。」

| よく出る形 | 直し方 | 理由 |
| --- | --- | --- |
| 〜である可能性があると考えられる | 根拠に合わせて「〜だ」「〜と推測している」のどちらかにする | 推量が重なって、どれくらい確かなのかわからない |
| 1段落にヘッジ（「〜ことがある」「〜場合がある」「〜可能性がある」）が2つ以上 | 根拠のあるものは言い切り、残りを一つにまとめる | 段落全体でどれくらい確かなのかわからない |
| あまり推奨されません／注意が必要です（判断がほしい場面の結論として） | 「非推奨」「〜しない」のように言い切る。手順書、ADR、レビューの指摘では特に | 根拠があるのに態度をぼかしている |
| 〜に他ならない | 主張の中身をそのまま書く | 根拠を足さずに、確かさだけを上げている |
| ケースバイケース／一概には言えません（文書の結論として） | 判断を書く。判断できないなら、できない理由を具体的に書く | 態度を示さないまま文を終えている |

「〜と言えるだろう」「かもしれない」のような推量は、根拠もなく主張を弱めているときだけ削り、根拠があれば言い切る。まだ確かめていない事実や、自信のない推測を書くときは残す（`SKILL.md`の「事実と推測を分ける」が優先）。

## 誰がするのかをたどれるようにする

日本語では、文脈でわかる主語は省ける。省いていいのは、誰の動作かを読み手が補えるときだけだ。誰がするのかを書かずに済ませるための受け身（「〜が求められる」「〜とされている」）は、誰が何をするのかを読み手から隠してしまう。

- 見るところ：その動作を誰がするのか、読み手が答えられるか。
- 悪い例：「リリース前に負荷試験の実施が求められる。」
- 良い例：「リリース前に、インフラチームが負荷試験をする。」

| よく出る形 | 直し方 | 理由 |
| --- | --- | --- |
| 対応が必要とされている | 〇〇チームが〇月〇日までに対応する | 誰が対応するのかわからない |
| 修正が求められる | レビューで指摘された点を〇〇が直す | 誰が求めていて、誰が直すのかわからない |
| 対応する／実施する／検討する（それだけで結論にする） | 担当者、作業の中身、期限を書く | 誰が何をするのかわからない |
| 業界の専門家によると／調査結果が示すように（出典を書かずに） | 「〇〇社が公表した△△調査では」のように具体的に書く。出せないなら自分の見解だと書く | 誰が言ったのかわからず、読み手が確かめられない |

主語のない受け身は、する人を主語にした文に直す。する人が本当にわからないなら、わからないと書く（「原因はまだわかっていない」）。

## 英語の構文を写さない

英語の構文をそのまま訳すと翻訳調になる。英語に直訳し戻すと自然な英文になるのに、日本語としては硬い文は、組み立てから見直す。

- 見るところ：日本語で一から書いても、同じ組み立てになるか。
- 悪い例：「このデータは、移行が予定どおり進んでいることを示している。」
- 良い例：「このデータから、移行が予定どおり進んでいることがわかる。」

| よく出る形 | 直し方 | 元の英語の型 |
| --- | --- | --- |
| 重要なのは〜である | 主張をそのまま書く | It is important to note that… |
| 本ドキュメントでは〜について見ていく | 結論から書く | In this document, we will explore… |
| 掘り下げる／深掘りする | 何をどう調べたか、何を書いたかを書く | delve into |
| データのすぐ後に「〜を示しており」「〜を物語っている」と続けて意味づけする | 「〜から〜がわかる」と書く。評価を書くなら、根拠になる数値や条件も書く | The data shows… / speaks to… |
| 「Xではない。Yだ。」「単なるXではなく、Yだ。」 | Yだけを書く | It's not just X, it's Y. |

## 長い修飾語を先に置く

日本語では、修飾語が修飾される語の前に積み重なる。修飾語がいくつかあるときは、長いものを先に、短いものを後に置く。長い修飾語の後に読点を打つと、どこまでが一つの修飾語なのかがわかりやすい。

- 見るところ：どの修飾語がどの語に掛かるか、一度読んで決まるか。
- 悪い例：「詳しく障害が発生した原因を調べる。」（「詳しく」が「発生した」に掛かるようにも読める）
- 良い例：「障害が発生した原因を詳しく調べる。」

## 前の文とのつながりを一つに決める

接続詞は、前の文とどんな関係にあるのか（因果、逆接、並列、補足）を表す。関係を決めないまま「また」「さらに」でつなぐと、論理を書かずに済ませることになる。関係が文脈で明らかなら、接続詞はなくていい。

- 見るところ：前の文との関係を一言で言えるか。言えるなら、その関係を表す接続詞にするか、削る。
- 悪い例：「キャッシュを無効にした。また、応答時間が2倍になった。」
- 良い例：「キャッシュを無効にした結果、応答時間が2倍になった。」

| よく出る形 | 直し方 | 理由 |
| --- | --- | --- |
| 1段落に「さらに」「また」「加えて」で始まる文が2つ以上 | 前の文との関係（因果、逆接、並列、補足）を決めて、それを表すつなぎ方にする。文脈で明らかなら削る | 関係を決めずに文を足している |

## 何をするかを具体的な言葉で書く

「適切に」「柔軟に」「多角的に」のような抽象的な言葉や、カタカナのビジネス用語は、何を指すのかの解釈を読み手に任せてしまう。何をどこまでするのかを、動作、対象、条件で書く。

- 見るところ：その言葉を読んで、読み手が同じ作業をできるか。
- 悪い例：「エラー時は適切にハンドリングする。」
- 良い例：「タイムアウトしたら3回まで再試行し、それでも失敗したら呼び出し元に例外を返す。」

| よく出る形 | 直し方 | 理由 |
| --- | --- | --- |
| 適切に処理する | 3回まで再試行し、失敗したらSlackに通知する | 何をするのかわからない |
| 柔軟に対応する | 設定ファイルで再試行回数を変えられるようにする | 何をするのかわからない |
| 基本的に問題ない | 〇〇の場合を除いて問題ない | どんなときが例外なのかわからない |
| 必要に応じて実施する | エラー率が5%を超えたら実施する | いつするのかわからない |
| 多角的に分析すると | 何をどう見たのかを書く | 何を見たのかわからない |
| 包括的に／総合的に | どこまでが対象なのかを書く | 範囲がわからない |
| 非常に／極めて／大いに | 数値や具体的な程度で書く | どの程度なのかわからない |
| 〜という形で／〜という観点から／〜という側面から | 新しい情報がなければ削る | 何も指していない |

カタカナのビジネス用語は、和語や漢語に言い換えられないか考える。API、デプロイ、リポジトリのように技術用語として定着している語はそのままでいい。カタカナ語が3つ以上続いたら、言い換えを疑う。

| よく出る形 | 直し方 |
| --- | --- |
| 〜にレバレッジを効かせる | 〜を活用する |
| ソリューション | 解決策、仕組み |
| イノベーティブな | 新しい、独自の |
| 〜にコミットする | 〜を引き受ける、必ず〜する |
| 〜をアラインする | 〜を揃える、〜を合わせる |
| 〜にディープダイブする | 〜を詳しく調べる |
| 〜をスケールする | 〜を拡大する |
| 〜にピボットする | 〜に方針転換する |
