# 事前確認

PRを作成する前に、変更内容・既存PRの有無・PRの言語を確認する。

## 変更内容の把握

```sh
git status --short
git log --oneline -10
git diff <base>...HEAD
```

`<base>`はマージ先ブランチ（例：`main`）。まだbaseが決まっていない場合は、デフォルトブランチ（`main`や`master`）に対して実行する。

確認すること：

- どのファイルがどう変わったか
- コミットが意味のある単位に分割されているか
- デバッグ用コード（`console.log`など）が残っていないか
- 無関係な変更が混ざっていないか

コミット分割が不適切な場合は、PR作成に進む前にユーザーへ相談する。

## 既存PRの重複確認

同じブランチからすでにPRが作られていないか確認する。

```sh
gh pr list --head <branch-name>
```

既存PRがある場合は新規作成しない。既存PRの更新（タイトル・本文の編集）が必要かユーザーに確認する。

## 検証コマンドの実行

リポジトリにlintやtestのコマンドが定義されていれば、PR作成前に実行する。

- `package.json`のscripts（`npm run lint`、`npm test`など）
- `Makefile`、`lefthook.yml`、CI設定（`.github/workflows/`）などから検証コマンドを特定する

検証が失敗した場合は、修正してからPRを作成する。失敗したまま作成する場合は、ユーザーに理由を確認する。

## PRタイトル・本文の言語判定

PRの言語はリポジトリの慣習に従う。以下で直近の履歴を確認して判定する。

```sh
git log --oneline -10
gh pr list --state all --limit 10
```

- コミットメッセージやPRが日本語中心なら日本語で書く
- 英語中心なら英語で書く
- 混在している場合は直近の傾向を優先する
- 判定できない場合（新規リポジトリなど）はユーザーに確認する

判定結果はタイトル・本文の両方に一貫して適用する。

## baseブランチの候補確認

baseブランチの決定自体はワークフローのステップ2で行うが、ここで候補を把握しておく。

- ユーザーが明示的に指定したか
- `git config branch.<current>.gh-merge-base`が設定されているか
- リポジトリのデフォルトブランチ（`gh repo view --json defaultBranchRef`で確認できる）
