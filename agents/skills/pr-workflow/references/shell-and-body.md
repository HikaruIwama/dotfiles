# 実行シェルの確認と本文の渡し方

PRを作成する前に、エージェントがコマンドを実行するシェルを確認する。以降のコマンドの書き方はすべてそのシェルに合わせる。

## シェルの確認方法

最初に以下を実行してシェルを判定する。

```sh
$PSVersionTable.PSVersion
```

- バージョンが表示されれば**PowerShell**（5.1または7系）
- 「コマンドが見つかりません」系のエラーなら**bash等のPOSIXシェル**

PowerShellの場合はバージョンも確認する。5.1では文字コード周りの挙動が7系と異なるため、区別が必要。

## 本文は必ず`--body-file`で渡す

PRの本文は`--body`に直接埋め込まない。必ず一時ファイルに書き出して`--body-file`で渡す。

```sh
gh pr create --title "feat: ログイン機能を追加" --body-file pr-body.md
```

### 理由

PowerShell（特に5.1）では、`--body`に複数行文字列や以下の文字を含む引数を渡すと内容が壊れる。

- バッククォート（`` ` ``）：PowerShellのエスケープ文字として解釈される
- `$`：変数展開される
- ダブルクォート：引用符のネストで壊れる
- 改行：コマンドライン引数内で正しく扱えない

bash環境でも同じ方法に統一しておけば、シェルごとの分岐が不要になり安全。

## 本文ファイルの作り方

本文ファイルはファイル書き込みツール（writeツール等）で作成する。シェルのリダイレクトやヒアドキュメントは使わない。

```powershell
# NG：PowerShell 5.1の">"リダイレクトはUTF-16LEで書き出すため壊れる
"..." > pr-body.md

# NG：ヒアストリングも同様に文字コードの問題がある
@"
...
"@ | Out-File pr-body.md
```

GitHubは本文をUTF-8として解釈する。UTF-16LEで書き出されたファイルは文字化けする。

ファイルは一時ディレクトリなどに作成し、PR作成後に削除してもよい。

## タイトルの渡し方

タイトルは1行なので`--title`で渡してよい。ただし以下に注意する。

- PowerShellで`$`やバッククォートを含む場合はシングルクォートで囲む
- ダブルクォートを含む場合はエスケープ方法がシェルで異なるため、タイトルにダブルクォートを使わないほうが無難

```powershell
# PowerShell：シングルクォートなら$やバッククォートが展開されない
gh pr create --title 'fix: $variableの参照エラーを修正' --body-file pr-body.md
```
