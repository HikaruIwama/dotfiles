# レビューチェックリスト

## 1. 機械的に検出できる項目（先にgrepで潰す）

人が読む前に、以下のパターンで一括検索して直す。ripgrepの例（活用形をまとめて拾うため、語幹の一部で検索する）：

```bash
rg '出来|下さい|する事|た事|事が|事は|為|無い|様々|更に|及び|但し|又は' <対象ファイル>
rg 'ことができ|ことが可能|という形|を行|に関しまして' <対象ファイル>
rg '[A-Za-z0-9`] [\p{Han}\p{Hiragana}\p{Katakana}]|[\p{Han}\p{Hiragana}\p{Katakana}] [A-Za-z0-9`]' <対象ファイル>
rg '[０-９]' <対象ファイル>
rg '先日|先週|今週|来週|先月|今月|来月|昨日|明日|最近' <対象ファイル>
rg '重要なのは|に他ならない|多角的|包括的|掘り下げる|深掘りする|という観点から|という側面から' <対象ファイル>
rg 'ケースバイケース|一概には言えません|業界の専門家によると|調査結果が示すように|を示しており|を物語っている' <対象ファイル>
rg '\*\*[^*]{1,20}[:：]\*\*' <対象ファイル>
rg '！|[\p{Han}\p{Hiragana}\p{Katakana}]!|―|—|～' <対象ファイル>
rg 'させていただ|おっしゃられ' <対象ファイル>
rg 'レバレッジ|ソリューション|イノベーティブ|コミットする|アライン|ディープダイブ|スケールする|ピボット' <対象ファイル>
rg '非常に|極めて|大いに' <対象ファイル>
```

ヒットした行がコードフェンス内かどうかを確認し、コードブロックの中身は対象外にする。

ヒットした箇所は基本的に`references/orthography.md`・`references/ng-phrases.md`の対応する置き換えを適用する。ただし「事」「為」を含むパターンは、「事件」「事故」「事業」「仕事」「大事」「工事」「行為」「為替」のような実質名詞の一部にもヒットする。形式名詞（〜する事、〜た事、〜という事が、〜の為）かどうかを確認してから置き換える。

- [ ] `SKILL.md`の「構成と論証の規則」のうち、事実と推測の分離、因果の機構を満たしている

- [ ] 前の段落との関係が、接続表現か文脈で明示されている

## 5. 文書全体

- [ ] `SKILL.md`の「構成と論証の規則」のうち、冒頭の結論、見出し、前方参照の規則を満たしている
- [ ] 見出しだけを並べて読んでも、文書の流れがわかる
- [ ] `SKILL.md`の「変更してはいけないもの」を変更していない

## 文書種別ごとの追加チェック

### 障害報告

- [ ] 時系列が発生順に並んでいる
- [ ] 事実（ログ・計測値）と推測が、文として分離されている
- [ ] 恒久対応の担当者と期限が明記されている

### ADR・設計書

- [ ] 決定した内容が、短い導入の直後（最初の実質的な節の冒頭）にある
- [ ] 決定の理由が書かれている
- [ ] 検討して却下した案が、却下理由とともに書かれている

### PR・Issueの説明

- [ ] 変更点が箇条書きまたは1段落で明確である
- [ ] 動作確認の方法が書かれている
- [ ] 影響範囲（互換性、既存機能への影響）が書かれている

### 手順書

- [ ] 操作指示が常体の終止形（「保存する」「再起動する」）で言い切られている
- [ ] 前提条件（環境、権限、事前に必要な作業）が手順の前に書かれている
- [ ] 条件分岐が「〜の場合は△△する」の形で、条件と操作が対応している

### UI文言・エラーメッセージ

- [ ] 文字数が画面の制約内である
- [ ] ユーザーの操作ミスを責める表現になっていない（「不正な入力です」→「入力内容を確認してください」）
- [ ] 次に何をすればよいかが示されている
