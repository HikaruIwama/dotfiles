# 作成前の要件確認

新規プロジェクトや設計上の選択が残る成果物では、ユーザーが決めるべき項目を確認してから計画を確定し、依存する実装に着手する。

## 未決項目を見つける

依頼内容と既存のコード、設定、規約を調べ、決定済みの項目、ユーザーから選定を任された項目、未決項目を分ける。「最小構成」「一般的な構成」などの言葉を、技術や仕様が決まった根拠にしない。

次の観点から、その依頼に関係する選択を確認する。該当しない項目や既存方針が明確な項目は質問しない。

- 作るもの：利用者、用途、主な振る舞い、成果物、完了条件
- 実装基盤：言語、フレームワーク、実行環境、パッケージ管理、プロジェクト構成
- 品質管理：formatter、linter、型検査、テストの対象・種類・ツール
- 運用：ビルド、CI、デプロイ先、環境変数の扱い
- 必要な場合：データ保存、認証、対応端末、アクセシビリティ、多言語対応

新規プロジェクトでは、実装基盤と品質管理のツールを使うかどうか、使うなら何を選ぶかも確認する。指定や明示的な選定の委任がないまま、採用・省略を決めない。

## 確認してから進める

結果や作り直しの範囲を大きく変える未決事項は、関連する質問をまとめてユーザーに確認する。選択肢を示すときは、推奨案とその理由、主な違いを簡潔に伝える。推奨案を示しただけで選択済みとは扱わない。

回答を受けたら、残った未決事項や回答から新たに生じた選択を見直す。一度質問したことだけを着手条件にせず、重要な選択が揃うまで必要な確認を続ける。回答を待つ間は、既存構成の調査など、選択に依存しない作業を進めてよい。

ユーザーが選定を明示的に任せた項目は、既存方針と制約を踏まえて決め、理由を伝える。後から容易に変えられる細部は自分で判断し、質問を増やさない。
